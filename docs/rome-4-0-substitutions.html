ROME 4.0 — Substitutions d'entités

Savoir par quel nouveau code remplacer un code ROME devenu obsolète (appellation, compétence, contexte de travail ou métier), pour garder à jour les codes que vous avez enregistrés.
ROME 4.0 - Substitutions d'entités v1 — 2 endpoints · 1 schéma
Base api.francetravail.io/partenaire/rome-substitutions/v1
Qu'est-ce qu'une substitution ? Le ROME évolue : d'une version à l'autre, certains codes sont retirés et remplacés par de nouveaux. Une substitution est le lien officiel « ancien code → nouveau code » pour une même famille d'entités — par exemple l'appellation 500725 remplacée par 504295 (codes tirés de l'exemple du schéma).

Pourquoi s'en servir ? Si votre application enregistre des codes ROME — dans des offres, des profils de candidats, des alertes, des statistiques — ces codes vieillissent avec le référentiel. Cette API permet de les remettre à niveau : pour un code d'origine, elle indique le code de substitution à utiliser désormais.
Substitution Substitution
Unique object · 1:1 — tableau 0:N sur la liste
Une ligne de la table de correspondance : un code d'origine, la famille du ROME à laquelle il appartient, et le code qui le remplace. La même structure sert aux deux endpoints : un objet seul quand on interroge un code, un tableau d'objets quand on liste tout un type.
code · codeSubstitution · typeEntite · obsolete · dateFin
Aucun champ déclaré obligatoire (pas de required) : tous peuvent manquer, en particulier quand la réponse est restreinte par champs.
Code d'origine — l'ancien code code
Facultatif string · 0:1
Le code tel qu'il existait avant le changement — celui que vous avez sans doute déjà en base. C'est aussi la clé de recherche : on interroge l'API avec ce code, dans le chemin de la requête.
code — « Code d'origine de l'entité » · ex. 500725
Paramètre de chemin {code} sur /substitution/{typeEntite}/{code}
Code de substitution — le code à utiliser désormais codeSubstitution
Facultatif string · 0:1
Le code qui remplace l'ancien dans le ROME : c'est la valeur à reporter dans vos données. Le schéma ne prévoit qu'un seul type d'entité par ligne, donc l'ancien et le nouveau code appartiennent à la même famille (une appellation remplace une appellation, un métier remplace un métier). La réponse ne donne que le code, pas son libellé.
codeSubstitution — « Code de substitution de l'entité » · ex. 504295
Type d'entité — de quelle famille du ROME il s'agit typeEntite
Facultatif string · enum · 0:1
Les substitutions sont rangées par famille : chaque ligne dit si le code est une appellation, une compétence, un contexte de travail ou un métier. Le type est obligatoire dans l'URL de la requête et répété dans la réponse. Le détail des quatre valeurs est dans l'onglet Référentiels.
typeEntite — APPELLATION · COMPETENCE · CONTEXTE-TRAVAIL · METIER
Validité — l'entité est-elle encore en vigueur ? obsolete · dateFin
Facultatif boolean · date-time · 0:1
Indique si l'entité est devenue obsolète et, dans ce cas, jusqu'à quelle date elle était valable. Le schéma parle de « l'entité » sans préciser laquelle : on comprend qu'il s'agit du code d'origine, mais ce n'est pas écrit.
obsolete — booléen, « définissant si l'entité est obsolete »
dateFin — date-time, « date de fin de validité (renseignée si l'entité est obsolete) »
Pas de date de début : la description de l'endpoint évoque des « dates de validité », mais seule dateFin existe.
Aucune valeur autorisée de champs ne contient obsolete ni dateFin : dès qu'on restreint les champs, ces deux informations disparaissent.
Des codes, pas de libellés — Pour savoir ce que recouvre un code (son intitulé, sa définition), il faut l'API qui le décrit : ROME 4.0 — Métiers pour les appellations et les métiers, ROME 4.0 — Compétences pour les compétences, Situations de travail pour les contextes de travail. Les API Métiers et Compétences portent elles aussi obsolete / dateFin sur leurs entités : elles disent qu'un code est obsolète ; celle-ci dit par quoi le remplacer.
Ce que le schéma ne dit pas — Remplacements en chaîne : si le nouveau code est lui-même remplacé plus tard, rien n'indique si l'API renvoie directement le dernier code ou seulement l'étape suivante ; par prudence, réinterrogez l'API avec codeSubstitution jusqu'à obtenir « aucune substitution ».
Un code remplacé par plusieurs : la réponse pour un code est un objet unique, avec un seul codeSubstitution ; ce cas n'est pas prévu.
Historique : la description promet de « tracer l'historique des modifications », mais la réponse ne décrit qu'un état ; seul le paramètre date permet de remonter dans le temps, et uniquement sur l'endpoint qui interroge un code.
Authentification — API du royaume /partenaire (client credentials). Scopes requis : nomenclatureRomeSubstitutions + api_rome-substitutionsv1. Attention, le scope de nomenclature diffère de celui des autres API ROME 4.0 (nomenclatureRome). Aucun jeton usager : on n'accède à aucune donnée personnelle, et tous les endpoints sont en lecture (GET).
Cette API manipule les codes des autres référentiels ROME sans les décrire. Les seuls vocabulaires qu'elle définit elle-même sont la liste des types d'entité, les combinaisons autorisées du sélecteur de champs, le format de date et les codes d'erreur.

Types d'entité 4 valeurs chemin {typeEntite} · Substitution.typeEntite

Les quatre familles du ROME pour lesquelles des substitutions sont publiées. La valeur s'écrit telle quelle dans l'URL — avec un tiret pour CONTEXTE-TRAVAIL ; une valeur hors liste renvoie une erreur 400 VALIDATION_ERROR. Le même enum sert pour le paramètre de chemin et pour le champ de la réponse.
Appellation1 / 4
  • APPELLATION L'intitulé concret d'un poste (ex. « Développeur / Développeuse web ») ; un métier en regroupe plusieurs.
Schéma : « codes des appellations professionnelles ». Décrites par ROME 4.0 — Métiers (/v1/metiers/appellation/{code}).
Compétence2 / 4
  • COMPETENCE Ce que la personne sait faire dans l'exercice d'un métier.
Schéma : « codes des compétences et savoir-faire ». Décrites par ROME 4.0 — Compétences (/v1/competences/competence/{code}).
Contexte de travail3 / 4
  • CONTEXTE-TRAVAIL Les conditions dans lesquelles le métier s'exerce (horaires, environnement, déplacements…).
Schéma : « codes des contextes et environnements de travail ». Décrits par ROME V4.0 — Situations de travail.
Métier4 / 4
  • METIER La fiche métier ROME elle-même (ex. M1805 — Études et développement informatique).
Schéma : « codes des métiers et professions ». Décrits par ROME 4.0 — Métiers (/v1/metiers/metier/{code}).
Périmètre — Le schéma ne dit pas si COMPETENCE couvre aussi les savoirs et les savoir-être, que l'API Compétences range parmi les compétences ; il ne cite que « compétences et savoir-faire ». Les autres entités du ROME (grands domaines, domaines professionnels, secteurs, centres d'intérêt, thèmes, catégories de savoirs…) n'ont pas de type de substitution, bien que les API Métiers et Compétences leur donnent aussi un drapeau obsolete. Enfin, l'exemple fourni pour le champ typeEntite (APPELLATION,COMPETENCE,CONTEXTE-TRAVAIL,METIER) n'est pas une valeur valide : le champ contient une seule valeur.

Réponses d'erreur 2 codes métier codeMetier · exemples de réponses

« Aucune substitution » n'est pas un incident : c'est la réponse normale pour un code qui n'a pas été remplacé. Mais l'API ne distingue pas un code jamais remplacé d'un code qui n'a jamais existé — pour vérifier qu'un code est valide, il faut passer par l'API qui le décrit. Le codeMetier n'est pas déclaré en enum : les valeurs ci-dessous viennent des exemples de réponses du schéma.
Code métier d'erreur2 valeurs
Requête mal formée HTTP 400
  • VALIDATION_ERROR Type d'entité inconnu (faute de frappe, ex. APPELLATIO) ou sélecteur de champs non autorisé
Aucune substitution trouvée HTTP 404 — ou 400
  • SELECTOR « Code inexistant: Aucune substitution trouvée pour le code '…' et le type … » — le code demandé n'a pas de substitution pour ce type
Le même message SELECTOR est documenté à la fois en 400 et en 404 sur /substitution/{typeEntite}/{code}, et le corps de l'exemple 404 indique "code": 400 : mieux vaut tester codeMetier que le seul statut HTTP. Corps d'erreur : service · message · code · codeMetier. Le message VALIDATION_ERROR d'exemple contient un %s non remplacé. Les erreurs 500 suivent un autre format : timestamp · status · error · path.

Remettre à jour des codes d'appellation après une évolution du ROME — Une plateforme d'offres d'emploi a enregistré des codes d'appellation ROME dans ses offres et dans les alertes de ses candidats. Après une mise à jour du référentiel, un traitement de nuit récupère la table des substitutions, puis vérifie des codes au cas par cas. Les codes 500725 → 504295 sont ceux de l'exemple du schéma, qui ne dit pas à quel type d'entité ils appartiennent : on les traite ici comme des appellations. La date de fin, le code 12374 et le détail de la réponse « aucune substitution » sont adaptés des exemples du schéma, à titre d'illustration.
// ────────────────────────────────────── // 1) Récupérer la table d'un type // GET /substitution/APPELLATION // ?champs=code,codeSubstitution // ────────────────────────────────────── // ─ Réponse 200 (tableau) ────────────── [ { "code": "500725", "codeSubstitution": "504295" }, // … une entrée par appellation remplacée ]
// ────────────────────────────────────── // 2) Vérifier un code précis // GET /substitution/APPELLATION/500725 // ────────────────────────────────────── // ─ Réponse 200 ──────────────────────── { "code": "500725", "codeSubstitution": "504295", "typeEntite": "APPELLATION", "obsolete": true, "dateFin": "2026-01-01T00:00:00.000+00:00" }
// ────────────────────────────────────── // 3) Un code sans substitution // GET /substitution/APPELLATION/12374 // ────────────────────────────────────── // ─ Réponse 404 (le schéma documente aussi 400) { "service": "/v1/substitutions-rome/substitution/APPELLATION/12374", "message": "Code inexistant: Aucune substitution trouvée pour le code '12374' et le type APPELLATION, (entite: Substitution)", "code": 400, "codeMetier": "SELECTOR" }

🔁 2 — Un code précis

500725 → 504295

L'appellation 500725 n'est plus en vigueur : dans les offres et les alertes, on la remplace par 504295.

Type → APPELLATION
Obsolète → oui
Fin de validité → 1er janvier 2026 (date illustrative)

La réponse ne donne aucun libellé : pour afficher le nouvel intitulé, on enchaîne sur l'API ROME 4.0 — Métiers (GET /v1/metiers/appellation/504295). Avant d'enregistrer 504295, on peut aussi le soumettre à son tour à cette API : le schéma ne dit pas si un code de substitution peut lui-même être remplacé.

Le paramètre date permet de poser la même question pour une date passée.
➖ 3 — Aucune substitution

12374 : rien à remplacer

Pour un code qui n'a pas été remplacé, l'API ne renvoie pas un objet vide mais une erreur SELECTOR « Code inexistant ». Pour le traitement, c'est la réponse attendue : on garde le code tel quel.

Substitution → aucune
Statut HTTP → 404 ici ; le schéma documente le même message en 400, et le corps indique "code": 400 — on se fie donc à codeMetier.

Cette réponse ne prouve pas que le code existe : un code mal saisi donnerait la même erreur. Pour le vérifier, on interroge l'API Métiers.
